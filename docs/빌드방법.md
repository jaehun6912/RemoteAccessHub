## 2. SDK 설치

이 저장소를 만든 PC에는 전역 .NET SDK가 없어, 관리자 권한 없이 사용자 폴더에 설치했습니다.

```powershell
# 공식 설치 스크립트를 내려받아 서명을 확인한 뒤 실행
curl.exe -sSL https://builds.dotnet.microsoft.com/dotnet/scripts/v1/dotnet-install.ps1 -o dotnet-install.ps1
(Get-AuthenticodeSignature .\dotnet-install.ps1).Status   # Valid 여야 함
.\dotnet-install.ps1 -Channel 8.0 -InstallDir "$env:LOCALAPPDATA\Microsoft\dotnet" -NoPath
```

설치 위치: `%LOCALAPPDATA%\Microsoft\dotnet`
`build.ps1`이 이 위치를 자동으로 찾습니다. 전역 SDK가 있으면 그쪽을 씁니다.

> 설치 중 압축 해제가 중간에 실패하면 설치 폴더가 불완전한 상태로 남고, 다시 실행해도 "이미 설치됨"으로 건너뜁니다. 그럴 때는 설치 폴더를 지우고 다시 실행하세요.

## 3. 빌드·검사·게시

```powershell
.\build.ps1                      # 복원 + 빌드 + 단위검사
.\build.ps1 -Publish             # + artifacts\publish 에 실행 패키지 생성
.\build.ps1 -SelfTest            # + 모의 공유기 자체검사 (WebView2 필요, 창이 잠시 뜸)
.\build.ps1 -Publish -Installer    # + artifacts 에 설치 파일(setup.exe) 생성
.\build.ps1 -Publish -SelfTest
```

개별 명령으로도 가능합니다.

```powershell
$dotnet = "$env:LOCALAPPDATA\Microsoft\dotnet\dotnet.exe"
& $dotnet build RemoteAccessHub.sln -c Release
& $dotnet test tests\RemoteAccessHub.Tests\RemoteAccessHub.Tests.csproj -c Release
& $dotnet publish src\RemoteAccessHub\RemoteAccessHub.csproj -c Release -r win-x64 --self-contained false -o artifacts\publish
```

> **주의:** 경로가 매우 긴 폴더(예: 임시 작업 폴더)에서는 NuGet/MSBuild가 `MSB3202` 오류를 냅니다. 짧은 경로에서 빌드하세요.

프로그램 아이콘(`src\RemoteAccessHub\Assets\app.ico`)은 `tools\make-icon.ps1`이 코드로 그린 파일입니다. 도안을 바꿀 때만 다시 만들고, 만든 파일은 저장소에 함께 올립니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\make-icon.ps1 -Preview .\icon-preview.png
```

16·20·24·32·40·48·64·256px이 들어 있고, 16px은 흐려지지 않도록 전원 표시를 픽셀 단위로 찍습니다.

## 4. 검사 종류

| 명령 | 내용 | 실제 공유기 접속 |
| --- | --- | --- |
| `dotnet test` | 단위 검사 215개. WOL 대상 매칭(실기기 구조 포함), 화면 판정, 클릭 안전 검사, 입력 검증, 세션 래치, 접속 흐름(일반·VPN·크롬 원격 데스크톱), 마스킹 | 안 함 |
| `RemoteAccessHub.exe --selftest <결과파일>` | 통합 자체검사 108개. 실기기 특성을 재현한 모의 공유기 + 실제 WebView2 + 실제 UI | 안 함 |
| `RemoteAccessHub.exe --router-check <출력파일> [--url <주소>]` | 실제 공유기의 화면 구조·세션 판정 확인 (로그인하지 않음) | **함** |
| `RemoteAccessHub.exe --mock` | 모의 공유기를 띄운 채 프로그램을 직접 조작 | 안 함 |

자체검사 옵션:

```powershell
.\RemoteAccessHub.exe --selftest .\결과.txt --screenshots .\화면캡처
```

자체검사는 실제 VPN·RDP를 실행하지 않습니다. `rasdial`, `rasphone`, `mstsc`는 가짜 구현으로 대체됩니다.

## 4-1. GitHub Actions

`.github/workflows/build.yml`: `main`·`master`에 올리거나 풀 리퀘스트를 만들면 Windows에서 빌드 → 단위 검사 → 게시 결과물(서명 없음, 14일 보관)을 만듭니다. 통합 자체검사는 창과 WebView2가 필요해 CI에서 돌리지 않습니다.

## 5. 게시 결과물

`artifacts\publish` (framework-dependent, win-x64):

```
RemoteAccessHub.exe            실행 파일
RemoteAccessHub.dll            프로그램 본체
Microsoft.Web.WebView2.*.dll   WebView2 래퍼
WebView2Loader.dll             WebView2 로더
*.runtimeconfig.json, *.deps.json
```

자체 포함(self-contained) 게시가 필요하면 `--self-contained true -p:PublishSingleFile=true`를 쓸 수 있지만, 파일이 커지고 서명 대상이 늘어납니다.

### 설치 파일

`installer\RemoteAccessHub.iss` (Inno Setup 6). `build.ps1 -Publish -Installer`로 `artifacts\RemoteAccessHub-setup-<버전>.exe`를 만듭니다(약 2.5MB).

```powershell
winget install --id JRSoftware.InnoSetup    # 처음 한 번
```

| 항목 | 내용 |
| --- | --- |
| 설치 위치 | 기본은 사용자 폴더(관리자 권한 없음). 설치 창에서 모든 사용자용으로 바꿀 수 있습니다 |
| 만드는 것 | 시작 메뉴 바로 가기, 제거 프로그램 등록, 바탕 화면 바로 가기(선택) |
| 설치 전 확인 | .NET 8 Desktop Runtime(x64)과 WebView2 런타임이 있는지 보고, 없으면 무엇이 필요한지 알린 뒤 계속할지 묻습니다 |
| 제거할 때 | 설정(`%APPDATA%\RemoteAccessHub`)과 기록(`%LOCALAPPDATA%\RemoteAccessHub`)을 지울지 묻습니다. 조용한 제거(`/VERYSILENT`)에서는 묻지 않고 그대로 둡니다 |
| 서명 | **없습니다.** 설치 파일도 SmartScreen에 걸립니다. 6번을 보세요 |
