# 코드 서명과 배포

## 1. SmartScreen과 Smart App Control은 다른 기능입니다

| | SmartScreen (평판 기반 경고) | Smart App Control (SAC) |
| --- | --- | --- |
| 언제 | 인터넷에서 받은 파일(Mark of the Web)을 실행할 때 | 모든 실행 파일 |
| 모습 | "Windows의 PC 보호" 파란 창 | 조용히 차단. 알림만 뜨거나 아무 반응 없음 |
| 사용자 우회 | [추가 정보] → [실행] 가능 | **우회 선택지 없음** |
| 끄기 | 설정에서 조정 가능 | 끄면 **Windows 재설치 전까지 다시 켤 수 없음** |
| 통과 방법 | 서명 + 평판 누적, 또는 사용자가 직접 진행 | 신뢰된 서명 또는 Microsoft 평판 서비스의 신뢰 판정 |

SAC를 끄는 것은 되돌릴 수 없는 조치이므로, 이 문서는 SAC를 끄는 방법을 해결책으로 제시하지 않습니다.

## 2. 이 PC의 현재 상태 (2026-09-14 확인)

```
VerifiedAndReputablePolicyState = 1      → Smart App Control 켜짐(적용 중)
UsermodeCodeIntegrityPolicyEnforcementStatus = 2  → 사용자 모드 코드 무결성 적용 중
```

같은 PC에서 어제는 차단되고 오늘은 차단되지 않았습니다.
**SAC의 판정은 파일별 평판에 따라 달라지며 시점에 따라 바뀝니다.**

## 3. 그래서 지금 상태는 무엇인가

- 개발 PC에서는 **현재 서명 없이도 실행됩니다.** 위 실측이 근거입니다.
- 그러나 이것은 보장이 아닙니다. 파일을 다시 빌드하거나, 다른 PC로 옮기거나, 며칠 뒤 평판 판정이 바뀌면 다시 차단될 수 있습니다.
- 따라서 **"보안 기능을 유지한 상태로 어디서나 배포 가능한 실행 파일이 완성되었다"고 말할 수 없습니다.**
- 자체 서명 인증서로 서명하거나 단순히 다시 빌드하는 것으로는 SAC 문제가 해결되지 않습니다. 자체 서명 인증서는 신뢰된 루트가 아니므로 SAC 판정에 도움이 되지 않습니다.

## 4. 신뢰된 서명을 갖추려면 (외부 자격이 필요한 부분)

현재 이 PC에는 코드 서명 인증서가 없고(`Cert:\CurrentUser\My`에 코드 서명용 인증서 0개), Windows SDK의 `signtool.exe`도 설치되어 있지 않습니다. 아래는 **사용자가 직접 준비해야 하는 것**입니다.

### 방법 A. 상용 코드 서명 인증서

1. 인증 기관(DigiCert, Sectigo, GlobalSign 등)에서 코드 서명 인증서를 구매합니다.
   - **OV(조직 인증)**: 개인 개발자도 발급 가능하지만 신원 확인이 필요하고, 발급 후에도 평판이 쌓이기 전까지는 SmartScreen 경고가 나올 수 있습니다.
   - **EV(확장 인증)**: SmartScreen 평판을 즉시 얻는 데 유리합니다. 비용이 더 비쌉니다.
2. 2023년 6월 이후 발급되는 코드 서명 인증서의 개인 키는 **FIPS 140-2 Level 2 이상의 하드웨어**(USB 토큰 또는 클라우드 HSM)에 보관해야 합니다. PFX 파일만 받아서 쓰는 방식은 더 이상 발급되지 않습니다.
3. 서명 시 **RFC3161 타임스탬프**를 반드시 포함하세요. 없으면 인증서 만료와 함께 서명이 무효가 됩니다.

준비되면 이 저장소의 `sign.ps1`로 서명할 수 있습니다.

```powershell
.\build.ps1 -Publish
.\sign.ps1 -Thumbprint <인증서지문>
```

### 방법 B. Microsoft Store 배포 (MSIX)

Microsoft 파트너 센터 개발자 계정(개인 계정 1회 등록비)이 필요합니다.
Store를 통해 배포되면 Microsoft가 서명하므로 SAC와 SmartScreen 문제가 해결됩니다. 다만 개인용 도구를 Store에 올리려면 심사와 패키징(MSIX) 작업이 필요합니다.

### 방법 C. 서명 없이 이 PC에서만 사용

현재 실측상 동작합니다. 차단이 발생하면 아래 5번을 따르세요.

### 방법으로 권하지 않는 것

- SAC 끄기: 되돌릴 수 없습니다.
- 자체 서명 인증서를 신뢰할 수 있는 루트 인증 기관 저장소에 설치: 시스템 전체의 신뢰 기준을 약화시킵니다.
- `-p:PublishSingleFile` 등으로 형태만 바꾸기: 서명 상태가 바뀌지 않으므로 SAC 판정과 무관합니다.

## 5. 실제로 차단되었을 때 확인하는 방법

차단 여부와 원인은 추측하지 말고 이벤트 로그로 확인하세요.

```powershell
Get-WinEvent -FilterHashtable @{
  LogName='Microsoft-Windows-CodeIntegrity/Operational'; Id=@(3077,3033)
} -MaxEvents 20 | Select-Object TimeCreated, Id, Message | Format-List
```

- **3077 이벤트에 파일 경로가 보이면** Smart App Control(또는 코드 무결성 정책) 차단입니다. 서명 없이 해결할 방법이 없습니다.
- **이벤트가 없고 파란 경고 창만 떴다면** SmartScreen입니다. [추가 정보] → [실행]으로 진행하거나, 파일 속성에서 [차단 해제]를 선택하세요.

```powershell
# SmartScreen 대상인지 확인 (Mark of the Web 유무)
Get-Item .\RemoteAccessHub.exe -Stream Zone.Identifier -ErrorAction SilentlyContinue

# 서명 상태 확인
Get-AuthenticodeSignature .\RemoteAccessHub.exe | Select-Object Status, SignerCertificate
```

## 6. 배포 시 주의

- ZIP으로 옮기면 압축을 푼 파일에 Mark of the Web이 따라붙어 SmartScreen 대상이 됩니다.
- 같은 폴더의 `WebView2Loader.dll`도 함께 있어야 실행됩니다.
- 이 프로그램은 관리자 권한을 요구하지 않습니다(`asInvoker`). 권한 상승을 요구하는 빌드는 만들지 마세요.
